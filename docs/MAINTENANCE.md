# 公式サイト運用メモ

このファイルは、公開サイトの更新担当者（AIを含む）のための簡単な手順書です。公開方針の優先順位は [AGENTS.md](../AGENTS.md)、権利関係は [CONTENT-POLICY.md](../CONTENT-POLICY.md)、ロゴは [brand/README.md](../brand/README.md) を参照してください。

## 公開の仕組み

- Repository: [c-a-p-engineer/copimism](https://github.com/c-a-p-engineer/copimism)（Public）
- 公開URL: https://c-a-p-engineer.github.io/copimism/
- GitHub Pages: `master` ブランチの `/docs` を公開。
- `docs/index.html`: ページ本文、刊行物カード、各商品へのリンク。
- `docs/styles.css`: 見た目、画面幅への対応。
- `docs/assets/logo/`: メイン・モノクロ・白抜き・アイコンのSVG。
- サイトは静的HTML/CSS。**ビルド・GitHub Actionsは不要**。

## 刊行物の追加・更新

正本は、[技術書典のサークルページ](https://techbookfest.org/organization/5zdy9h5eA5kDzByP9rserV)と、そこから辿れる各商品ページです。

1. **サークルページに表示されていること**を確認する。商品ページIDや書名を推測しない。
2. 各作品について正式書名、商品URL、商品説明、初出イベント、ページ数、公式画像の参照先を確認する。
3. `README.md` の表と `docs/index.html` のカードを同時に更新する。並び順を変えるなら両方を同期する。
4. **「発行日」**は書籍の奥付などで確証が得られたときだけ書く。現在表示している**「初出イベント開始」**は開催開始日であって発行日ではない。
5. 書影は技術書典の商品OGP画像を参照する。画像のダウンロード・リポジトリへのコピーは、著作権者や配信元の条件を確認してから行う。
6. 新しい作品の情報を掲載する際、書影と販売リンクが開けるか確認する。未登録・未公表の作品は載せない。

### 書誌情報の確度

| 情報 | 一次資料 | 未確認時 |
| --- | --- | --- |
| 掲載対象・書名・商品URL | サークルページ、商品ページ | 掲載しない |
| ページ数・初出イベント | 商品ページ | 数値・イベント名を推測しない |
| 初出イベント開催日 | 技術書典の開催告知 | 空欄、未確認と表示 |
| **正式な発行日** | 当該書籍の奥付、発行元の正式記録 | **発行日未確認** |
| 書影 | 公式商品画像または権利確認済みの原本 | 画像なし・代替テキストで表示 |

## ロゴ・サイトの変更

- 正式表記は **こぴみずむ / COPIMISM**。
- ロゴ・ブランドのデザインは保護する。現在はVer.2採用候補であり、実寸サイズの最終判断待ち。
- 色、形、アンダースコアの位置、アイコン `>こ_` の変更を勝手に行わない。
- ロゴの権利・ライセンス文言は [ブランドガイド](../brand/README.md) と [コンテンツ利用条件](../CONTENT-POLICY.md) を維持する。
- HTML/CSSはMIT対象だが、そのファイルに含まれる独自文章・画像・ロゴは別扱い。CC BYとして扱わない。

## 公開前チェック

- [ ] 書籍はすべて技術書典公式サークルページの掲載作品だけ
- [ ] READMEとサイトで書名・作品数・販売リンクが一致
- [ ] 日付の種類が明記され、イベント開始日を発行日と誤認させない
- [ ] 外部画像・リンクの参照先が正しく、代替テキストがある
- [ ] PC・スマートフォンの表示と日本語の読みやすさを確認
- [ ] ロゴ・文章・画像の権利表示を維持
- [ ] 個人情報・非公開リポジトリ・未公開原稿・資格情報を混入させていない
- [ ] 不要なワークフロー、トラッキング、依存ライブラリを追加していない
- [ ] GitHubの変更反映と、公開Pagesの実画面確認を区別して記録

変更を確認できない場合は、その項目を「未確認」として残す。内容の追加そのものを目的化しない。

## 不具合対応

- 公開URLが404：まず `Settings → Pages` で `master` / `/docs` の設定を確認。勝手にPages構成やworkflowを作り替えない。
- 書影が表示されない：技術書典側の画像URLが利用可能か確認。取得できない場合、無関係な仮画像で代用しない。
- 表示崩れ：`docs/styles.css` の最小修正で対応し、モバイル幅を再確認。
- 誤った情報の公開：確認済みの一次資料を優先して訂正。原因を短く記録し、未確認の記述を増やさない。
- 権利の問い合わせ：[GitHub Issues](https://github.com/c-a-p-engineer/copimism/issues)で管理。機密・個人情報は公開Issueに記載しない。

## 終了条件

目的に必要なファイルだけ更新し、少なくとも出典と差分を確認できたら完了。重要な未確認事項は、完了として偽らず残課題として報告する。
